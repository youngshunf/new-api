# 语音资源实现

权威基线为父仓语音施工 §4.1 与网关 04 §4.4.1。本仓资源属于稳定 NewAPI `user_id`；短寿命租约 Token 只作创建审计。凭据和费用沿用普通 `generic/legacy` Relay 与 `BillingSession`。

## 持久化

正式迁移 `V003__远端音色资源.sql` 建立 `voice_profiles`，不交由上游 `AutoMigrate` 创建。`voice_ref` 为 NewAPI 铸造的 UUIDv7 主键，同时直接作为网关私有资源标识。`user_id + idempotency_key_digest` 为创建唯一键；幂等键保存 SHA256，避免三方言文本排序规则改变键的身份。请求摘要独立记录，供同键异请求返回 409。

首次创建必须先提交 `unknown` 再向供应商派发一次。重入只返回原记录；供应商 ID 缺席不能重建。渠道和目标模型固定在创建记录中，查询、删除与合成沿原渠道执行。`creator_token_id` 不参与所有权判定。

`delete_requested_time` 表示已封禁新合成；`delete_dispatched_time` 表示删除已占用唯一派发资格；只有成功供应商删除回执才写入 `deleted_time` 与 `state=deleted`。保留策略为 `provider_unused_one_year`。资源业务表不存原始材料、试听字节或临时文件路径。

`model/voice_profiles.gen.go` 由 `tools/modelgen -table voice_profiles` 读取 runner 创建的真实隔离 PostgreSQL 表生成。runner 核真实列类型、可空性、主键和唯一索引；账本存在不能代替目标 schema 验证。

## 验证边界

`VC7_SCHEMA_MATRIX=1 GOMAXPROCS=2 go test -p 2 ./tests/model -run 'Test(Voice|FormalMigration|AudioSchemaCannotBeCreated)' -count=1 -v` 使用真实 SQLite、PostgreSQL 和 MySQL。网络数据库固定为 `vc7_newapi_voice`，执行 fresh、从此前 V001/V002 升级、二次幂等、旧 Token 数据保留、唯一约束和错误同名索引反例。模型公共时间在三库逐毫秒往返一致。该命令属于数据库专项，不是 E2E。

## 供应商接入依据

首批接入 `cosyvoice-v3.5-plus`。建档、查询和删除均调用百炼 `voice-enrollment` 的 HTTP customization 端点；合成复用既有 Ali `AudioHelper` 与普通 Relay 费用流程。

- [声音复刻 HTTP API](https://help.aliyun.com/zh/model-studio/voice-clone-design-http-api)
- [声音设计 API](https://help.aliyun.com/zh/model-studio/voice-design-api-references)
- [CosyVoice HTTP TTS](https://help.aliyun.com/zh/model-studio/cosyvoice-tts-http-api)

`model/voice_profile.go` 提供唯一创建资格、按稳定账号恢复、审核状态投影、删除单派与合成前核验。三库状态专项包含并发八次同键只有一次派发资格、租约 Token 换代不改变归属、异摘要冲突、unknown 不重建、删除无回执仍 pending、删除请求立即封禁合成以及已删状态不能复活。测试不派发供应商请求，真实远端验收由后续 API 切片承担。

HTTP 路由、供应商派发、临时件回收与 TTS 入口绑定为后续切片。
