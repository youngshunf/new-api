# 语音资源实现

权威基线为父仓语音施工 §4.1 与网关 04 §4.4.1。本仓资源属于稳定 NewAPI `user_id`；短寿命租约 Token 只作创建审计。凭据和费用沿用普通 `generic/legacy` Relay 与 `BillingSession`。

## 持久化

正式迁移 `V003__远端音色资源.sql` 建立 `voice_profiles`，不交由上游 `AutoMigrate` 创建。`voice_ref` 为 NewAPI 铸造的 UUIDv7 主键，同时直接作为网关私有资源标识。`user_id + idempotency_key_digest` 为创建唯一键；幂等键保存 SHA256，避免三方言文本排序规则改变键的身份。请求摘要独立记录，供同键异请求返回 409。

首次创建必须先提交 `unknown` 再向供应商派发一次。重入只返回原记录；供应商 ID 缺席不能重建。渠道和目标模型固定在创建记录中，查询、删除与合成沿原渠道执行。`creator_token_id` 不参与所有权判定。

`delete_requested_time` 表示已封禁新合成；`delete_dispatched_time` 表示删除已占用唯一派发资格；只有成功供应商删除回执才写入 `deleted_time` 与 `state=deleted`。保留策略为 `provider_unused_one_year`。资源业务表不存原始材料、试听字节或临时文件路径。

`model/voice_profiles.gen.go` 由 `tools/modelgen -table voice_profiles` 读取 runner 创建的真实隔离 PostgreSQL 表生成。runner 核真实列类型、可空性、主键和唯一索引；账本存在不能代替目标 schema 验证。

## 验证边界

`VC7_SCHEMA_MATRIX=1 GOMAXPROCS=2 go test -p 2 ./tests/model -run 'Test(Voice|FormalMigration|AudioSchemaCannotBeCreated)' -count=1 -v` 使用真实 SQLite、PostgreSQL 和 MySQL。网络数据库固定为 `vc7_newapi_voice`，执行 fresh、从此前 V001/V002 升级、二次幂等、旧 Token 数据保留、唯一约束和错误同名索引反例。模型公共时间在三库逐毫秒往返一致。该命令属于数据库专项，不是 E2E。

## 供应商接入依据

首批接入 `cosyvoice-v3.5-plus`。建档、查询和删除均调用百炼 `voice-enrollment` 的 HTTP customization 端点；合成复用既有 Ali `AudioHelper` 与普通 Relay 费用流程。

- [声音复刻 HTTP API](https://help.aliyun.com/zh/model-studio/voice-clone-design-http-api)
- [声音设计 API](https://help.aliyun.com/zh/model-studio/voice-design-api-references)
- [CosyVoice HTTP TTS](https://help.aliyun.com/zh/model-studio/cosyvoice-tts-http-api)

`model/voice_profile.go` 提供唯一创建资格、按稳定账号恢复、审核状态投影、删除单派与合成前核验。三库状态专项包含并发八次同键只有一次派发资格、租约 Token 换代不改变归属、异摘要冲突、unknown 不重建、删除无回执仍 pending、删除请求立即封禁合成以及已删状态不能复活。测试不派发供应商请求，真实远端验收由后续 API 切片承担。

HTTP 路由由 `router.SetVoiceRouter` 注册，统一继承普通 TokenAuth 与限流。创建与五项读写面通过 `middleware.PrepareVoiceResource` 核稳定账户、组∩名单及原渠道；unknown 恢复和本地试听不依赖在线渠道。普通 TTS 在分流前钉原渠道，`AudioHelper` 出站前再次现核 ready、账号、原模型、未删除与渠道，然后替换供应商 ID；模型映射不得把该音色转到另一个目标模型。

## 普通调用租约约束

`V004__普通调用用途约束.sql` 在原 `tokens` 增加 `operation`，仅可信内部租约入口可写。Runtime 在 wire 省略该字段并使用空模型名单；普通 call 仍为 `generic/legacy`，必须携带闭集用途与恰好一个模型。TokenAuth 依据 Gin 已匹配的 HTTP 方法和路由核用途，再进入模型组与单模型名单求交及渠道选择。`audio.tts` 不允许音色创建、查询或删除；查询用途包含幂等恢复与试听。普通 Token 编辑不能清空内部租约约束；渠道 pin 不能绕过名单。

HASN 受管 Runtime（`external_lease_id` 非空、`operation` 缺席）保留模型列举与普通推理，但禁止五条音色持久资源入口。门禁复用上述用途路由表，在解析材料、读档案、写占位、试听或供应商派发之前拒绝；传统普通 API Key 保留公开入口行为。真实 SQLite 与 `SetRelayRouter` 专项逐条核五路 403、档案零读取与零修改、媒体不回收、供应商零派发，并核传统 Key 五路仍可访问及 Runtime 普通 TTS 仍到达真实 TCP 故障端点。数据库夹具与故障端点只验证消费者边界，不作为供应商成功证据。

私有 PUT 严格要求七个基础字段，拒绝未知字段、重复键、null 与尾随 JSON；不接受用途和账务模式默认值。同一 `external_lease_id` 的用途及账务模式终身不变，同代仅完整同规格幂等，异规格返回 `409 lease_conflict`。改变模型组、模型名单或期限必须升代并换 Key。跨副本更新核旧代、旧 Key、用途和完整旧规格 CAS。撤销保留软删除墓碑，任何代号重投都返回 `409 lease_conflict`；重新授权必须使用新的 `external_lease_id`。旧状态 CAS 同时核验 `status` 与 `model_limits_enabled`，避免乱序撤销后被 PUT 复活。

临时媒体使用 `service.VoiceMediaStore`，部署实例独占目录。参考原件上限 10 MiB、单次令牌 10 分钟；设计试听上限 8 MiB、保留 1 小时；目录总额 256 MiB、最多 1024 项。磁盘元数据记录 TTL、大小与写入状态，令牌仅存 SHA256；重启执行回收仍能追踪未完成写入、已消费及过期文件。单次取件先原子改名再返回句柄，关闭句柄删除原件与元数据。`InitResources` 初始化媒体目录并在启动时、每分钟执行回收；写入内容和目录改名均执行 Sync，失败显式拒绝。公开材料路由只由单次令牌取件，试听仍须账号及用途鉴权。

首批百炼 CosyVoice 的 clone/design 建档按[声音复刻指南](https://help.aliyun.com/zh/model-studio/voice-cloning-user-guide)与[声音设计指南](https://help.aliyun.com/zh/model-studio/voice-design-user-guide)的创建免费语义处理。创建沿现有 `BillingSession`，原生计价模型为 `voice-enrollment`：运营显式配置已有按次价格时照常收费，未配置时仅在该已核供应商路径按零费用处理，仍核账户与额度。query/delete 免费；design 自带试听只缓存，不额外派合成。clone 的固定试听走普通 `audio.tts` 字符计价。未知供应商不得用未配置价格推断免费，不新增账本或 Token purpose。

百炼协议适配在 `relay/channel/ali/voice.go`，创建/查询/删除都用 customization POST，沿现有渠道请求器处理代理、HeaderOverride 与派发追踪。创建无供应商 ID、查询模型/状态不符、删除缺少 request_id 或空 output 回执时均显式失败；HTTP 404 不当删除成功。设计试听先有界 base64 解码并实际解析 WAV/PCM，再交媒体存储。CosyVoice 普通 TTS 使用 SpeechSynthesizer HTTP、24kHz input 参数；供应商返回的下载 URL 使用原 SSRF 保护客户端。适配专项是请求/解析单元与真实 TCP 断连、307/308 单派验证，不替代供应商整链验收。

真实 HTTP + SQLite 消费者专项与 SQLite/MySQL/PostgreSQL fresh、V001/V002 升级、二次迁移共同验证用途持久化、换代、同代冲突与撤销墓碑。测试还通过临时移除严格解码及墓碑查询证实拒绝断言能够失败。

## HTTP 与部署

五条资源入口是 `POST /v1/audio/voices`、`GET /v1/audio/voices?idempotency_key=...`、`GET /v1/audio/voices/:voice_ref`、`GET /v1/audio/voices/:voice_ref/preview` 和 `DELETE /v1/audio/voices/:voice_ref`。创建与读写直接返回 `dto.VoiceResource`，HTTP 200 可表达 unknown、failed 或 delete_pending，不能据此宣称 ready。错误沿 OpenAI error 对象。设计仅 JSON；克隆仅 multipart，DTO 严格拒绝重复、null、未知字段、歧义大小写、过量正文与越界文本。供应商仍验证上传音频的格式和质量。

`VOICE_MEDIA_DIR` 为实例独占持久目录，默认 `./data/voice-media`；`VOICE_PUBLIC_ADDRESS` 必须是运营配置的可信公网 HTTPS origin，克隆缺席时在创建占位和派发前拒绝，不能使用请求 Host 推导。反代公开 `/v1/audio/voice-materials/:token`，不得将该路径缓存；部署实例须能主动访问原百炼渠道，并可被百炼回取材料。开发/验收实例应使用独立数据库、媒体目录、端口与只含测试渠道的配置，不改共享实例或复制整个开发栈。

模型库存只在 `models.endpoints` 显式增加 `hasn_audio_voice` 与 `openai_audio_speech`：前者默认 POST `/v1/audio/voices`，后者默认 POST `/v1/audio/speech`；不会因 Ali 类型或 CosyVoice 名称自动发布。推荐元数据：

```json
{"hasn_audio_voice":{"path":"/v1/audio/voices","method":"POST"},"openai_audio_speech":{"path":"/v1/audio/speech","method":"POST"}}
```

本片真实 HTTP + SQLite 使用完整生产路由，验证 TCP 完整收件后断连保持 unknown、同键不重派、离线恢复、异摘要 409、跨 Token 读面、跨账号 404、组∩名单、无 ID 删除 pending、缺试听 404、WAV 二进制与公开材料单次消费。克隆正文残缺、重复字段、缺文件或可信取件地址缺席时，在占位与派发前拒绝；供应商明确拒绝形成的 failed 同键也只能返回原记录。另以真实 TCP 故障核普通 TTS 出站使用供应商 ID 且只派发一次；ready/failed 的消费测试显式以数据库状态夹具核边界，不冒充供应商回执取证。显式按次价格的不足额度反例在派发前拒绝。临时移除离线恢复分支会使专项得到 403 而失败。三方言 schema、生命周期与普通租约专项继续通过。隔离入口已部署，2026-10-11 真人clone与文字design均真实建档ready并收到删除ACK，两次TTS实际计费守恒；WAV头完整性失败已留证并补下述codec修复，尚待修复制品完整链复验，E2E未运行。

NewAPI 的 `state=ready` 仅表示供应商审核通过；节点仍须得到本地试听 Asset 才能进入自身 ready。设计试听缺失、损坏或过期时 `preview_available=false` 且试听 GET 返回确定 404，不能重建音色；审核通过后可用同一 `voice_ref` 经普通 TTS 另做试听。

## WAV 完整性

2026-10-11 真实隔离供应商验收发现 CosyVoice TTS 完整响应为标准44字节 PCM16/mono/24kHz 头，但 RIFF/data 长度为 `0x7fffffbf`/`0x7fffff9b` 占位组合；实际 PCM 完整帧只有311040字节。原始透传会让严格 Asset/WAV 消费者按声明长度读取而失败。首个 clone 试听未通过，随后 design 诊断保留完整原响应，两个资源均收到真实删除ACK，未把供应商 ready 视为试听通过。

`relay/channel/ali/wav.go` 在既有64MiB有界完整下载后验证PCM与所有chunk。仅上述已取证长度组合、标准44字节头、合法PCM16/mono/24kHz和非空完整帧可重写两个长度，PCM逐字节不变。标准PCM WAV原样返回；其它长度矛盾、截断、空数据、异常fmt、未对齐或重复data均显式拒绝。TTS出口与设计preview解码复用同一严格边界，避免两个音频出口行为漂移。设计原preview已随删除回收，其真实头形尚未保留取证，不能从TTS推断。

仓内只保存真实44字节头及来源SHA，不提交真人或合成声音；PCM单位向量仅用于结构反例，不作为供应商成功证据。完整真实design响应留外置验收目录，另核重写后标准WAV可解码及PCM SHA不变。此次供应商直接专项不替代Node→Core→NewAPI完整E2E，Windows/Linux GPU发行仍未取证。
